## Important Current Decisions

- A **Vector Loom file** is a user's collection of designs, styles, and later
  assets and metadata. It is not called a Vector Loom package.
- For now, the Python distribution has one import package, `vectorloom`.
  Editor and viewer are planned as subpackages and later runnable entry
  points, not separate distributions yet.
- Connector records are immediate-mode render by-products. `instance_id` is a
  render identity label, not a promise of durable instance state.
- Future retained instances, assembly, and mutation remain possible but are
  deliberately not committed. See #0018 and ADR 0005.
- `READS` in BAD module documents means runtime reads only. Development-time
  references belong in `See Also`.
- Pseudocode should express the machine and its decisions, not incidental
  Python details. Keep explicit `def` signatures when they communicate the
  intended public API.

## Intended BAD Structure

```text
pseudo-src/
  project/
    project-profile.md
    adr/
  vectorloom/
    readme.md
    aspects/
    data-structures/
    interfaces/
    modules/
      core/
      tkinter/
      formats/
      editor/
      viewer/
```

`pseudo-src/vectorloom/modules/` mirrors the renderable path below
`src/vectorloom/`. The package-level `aspects/`, `data-structures/`, and
`interfaces/` describe cross-module material rather than Python directories.

## Notes for a Future Context Window

Start the next phase in `pseudo-src/`, not by moving Python files. First make
the mirrored BAD directories and write a migration map for the current
proving-ground modules.

The intended responsibilities are:

- `core/`: format-independent traversal, geometry, and transforms;
- `tkinter/`: Tk runtime, Canvas realization, Canvas tags, and the current
  immediate-mode connector registry;
- `formats/`: Vector Loom file reading and validation;
- `editor/`: the runnable editor, consuming the other layers;
- `viewer/`: later, a read-only application sharing the load-and-display path.

The shortest route to an editor is: establish the core/Tkinter BAD split, add
a narrow VectorLoom Basic reader in `formats/`, then build an editor shell that
loads a Vector Loom file and previews it. Do not wait for a full editor or a
separate viewer before getting that shell alive.
